# Operations

What to type, and what will bite you. `uv run autogeoref <command> --help` is
the full option reference.

Run everything from the Linux checkout. A Windows-side `uv run` against this
tree destroys `.venv`; `make setup` restores it.

## Where things stand

```sh
make status                                              # every volume, read from disk
uv run autogeoref queue --candidates --city <city-config>
```

Don't copy counts or queue state into documentation. They change as work
completes.

A volume with images but no `status` row has the wrong directory layout.
`status` also names sheet images whose filenames carry no parseable page id,
which the pipeline would otherwise skip in silence.

## Place a volume

```sh
uv run autogeoref prep <volume> --work work
uv run autogeoref run <volume> --city <city-config> --work work --dry-run   # prices it
uv run autogeoref run <volume> --city <city-config> --work work             # spends
uv run autogeoref report <volume> --work work
```

Declare the volume's address era and bounds before the first real run. Read the
report before doing anything else. A suspiciously high acceptance rate is a red
flag, not a win.

`run` does placement only unless you pass `--warp`. For a volume already
placed, use `--warp-only` (see [Bake](#bake)); `--warp` would repeat placement.

### Escalation

Re-annotates rejected sheets with a stronger model, cheapest tier first. One
corrected label can be the difference between a poisoned fit and a clean one.

- `escalation_models` on the city or volume, or `escalation_model` for one
  tier. No ladder means no stage. `escalation_models = []` on a volume cancels
  the city ladder. `--no-escalate` skips one run.
- A page stops at the first tier that passes the full gates. Gates are never
  loosened for an escalated read.
- Only pages whose corridor extraction finds at least
  `escalate.MIN_JUNCTIONS_TO_ESCALATE` drawn junctions are escalated. Most
  flagged sheets are label-poor or empty land.
- Each tier caches to `annotations/p<N>.escalated.<model>.json`. A tier that
  can't produce an annotation writes a failure marker and the ladder continues.
  **Those markers are the retry ledger.** A marked page reads as cached, so
  delete a marker to retry that tier; nothing re-spends otherwise.
- Tiers may mix providers (`["claude-sonnet-5", "openai-api:gpt-5.6-terra"]`).
  One model over both its transports is two tiers and two voices, because the
  CLI wraps it in an agent harness. Two spellings of one transport is one
  voice.
- A reported budget or usage limit kills the whole stage. An ordinary 429 is
  back-off pressure and retries.

### Grading against volunteer pins

Scoring is a separate pass over a finished tree. No pin reaches a run and
nothing in the pipeline reads a score.

```sh
uv run autogeoref score <volume> --work work
```

Reads `fixtures/ground-truth/api-layers-<volume>.json`, writes
`work/<volume>/results-scores.json`. Prints the median and worst scored accept
and every page beyond the 15 m commit gate by name. Spends nothing, changes no
placement, takes the volume lock.

- **A page beyond the gate is a finding.** Nothing is withdrawn automatically:
  it keeps vouching, seaming, and serving until you act on the number.
- **Re-score after a re-place.** Each entry records the SHA-256 of the record
  it graded, so a moved placement drops its score on read. The volume reports
  as unscored until you run this again.
- No export at all is reported as unchecked and **nothing is written**, so a
  mistyped `--ground-truth` can't erase a real grading. An export that exists
  but pins nothing (`[]`, or a 0-byte marker) means this volume was never
  pinned; that is a result and the sidecar records it.
- `--ground-truth <dir>` repeats to grade against a second corpus. Where both
  carry a page, the first named wins.

### Address eras

```sh
uv run autogeoref era <volume> --city <city-config>
```

Required on every pre-renumbering volume in a city that has a renumbering
table, before you enable the addresses channel. It proposes from catalog
metadata and requires confirmation. `docs/ADDING-A-CITY.md` §4 says why it is
never inferred.

## Alias sweeps

A sheet drawn before a street was renamed carries a name modern centerlines
don't hold, so its reads match nothing. The fix is a volume alias table.

```sh
uv run autogeoref alias-sweep --city <city-config> --work work --dry-run
uv run autogeoref alias-sweep --city <city-config> --work work
```

No model spend, no network, no re-place, no bake. Merge-only and idempotent, so
it is safe to run after a hand-built table lands: hand-checked entries win.
It scans every annotated volume and skips the ones that need nothing, so
running it corpus-wide is normal. `--force` re-does marked volumes.

Run it after annotating a volume, or after any change to the centerline
reference or a volume's bounds.

One prerequisite per city: the pinned rename source's text. It is third-party
and not committed, so extract it offline into the path `rename_source_text`
names. For Chicago:

```sh
uv run --offline --with pypdf python -c "
from pathlib import Path; from pypdf import PdfReader
r = PdfReader('cache/renumbering/chm_namechanges.pdf')
Path('cache/renumbering/martin1948.txt').write_text(
    chr(10).join(p.extract_text() or '' for p in r.pages))"
```

A city with no `rename_source_*` is scanned, reported, and never proposed for.
A city with no `address_grid_*` loses the numeral check, which shrinks what can
be auto-written.

### The report

`--report`, default `work/scratch/alias-sweep-report.md`:

| Section     | What to do with it                                                                                                                                                                  |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Scan**    | One row per volume with before/after match rates and why anything was skipped. Nothing is skipped silently.                                                                         |
| **Written** | The clean tier, already on disk. A _"Supersedes a recorded disposition"_ note means the file's prose still says that key was deliberately not aliased. Rewrite the comment by hand. |
| **Aborted** | The merged table failed a structural rule. Nothing was written, exit is nonzero. Read the rule; don't relax the validator.                                                          |
| **Held**    | A queue, not a discard pile. Each row names what evidence it needs.                                                                                                                 |
| **Refused** | No candidate is reachable. Not a queue. Read it for surprises.                                                                                                                      |

Held reasons and their fix:

- _locality measured on 1 sheet_: find a second sheet, or a precedent.
- _no measurable locality_: the co-reads are parallel (numbered avenues). Use
  the ordinal-structure check.
- _numerals did not corroborate_: decide by hand or leave it.
- _diverging printed directions_: needs direction-qualified keys, by hand.
- _breaks the structural rules_: usually a bare numbered key that would drag
  its PLACE/COURT twin along. The qualified key is the fix.

The sweep changes what _matches_, not what places. It prints the re-place
command per volume but never runs it, because whether that is free depends on
the volume: `--no-escalate` demotes escalation-won accepts, and leaving
escalation on spends fresh wherever cached tiers no longer match the city
ladder. Check the volume's cached tiers against the city ladder before
re-placing it.

### Verifying tables on disk

```sh
uv run python scripts/validate_alias_files.py --work work
uv run python scripts/validate_alias_files.py \
    --city configs/cleveland/cleveland.toml --work work/city2-probe
```

Run it after any hand edit. **One city per run and the default is Chicago**, so
the second command is not optional: a city nobody points it at is a city
nothing checks. Point `--work` at a populated tree, or volumes whose bounds
can't resolve are skipped rather than judged.

`PRE_EXISTING` is a countdown of real violations awaiting repair. Never delete
an entry to go green, and never add one for a correct entry.

Two printed notes are not failures. `[N inert]` counts entries that can't
change any outcome. `[N redirect(s)]` lists entries taking reads away from a
street still in bounds, which is the shape of a one-directional rename and also
the shape of a mistake. Read those lines; a wrong one is invisible everywhere
else.

## Queues

Three tracks drain in parallel, each promoting a success to the next: `fetch`
downloads jp2 masters from LOC, `place` runs the model-spending workflow,
`serve` runs the GDAL back half.

```sh
uv run autogeoref queue --track fetch --add <volume>
uv run autogeoref queue --run --city <city-config> --stop-on-failure
```

`fetch` is the only track that needs no work tree, so it is where a new volume
starts. Every other enqueue refuses a volume with no tree and names the fetch
command. A fetched volume is not ready to place: declare its era and bounds
first.

`scripts/fetch_loc_volume.py` is the implementation and works with no queue
(`--dry-run` prices the LOC pacing floor). It writes `work/<vid>/jp2/` for the
masters and `work/<vid>/regions/` for the pipeline's inputs. Nothing on disk is
re-fetched, so a re-run costs only what the last pass missed. One lane, spaced
at five seconds or more.

### When a drain stops

**Use `--stop-on-failure` whenever a model limit is plausible.** Without it the
drain takes the next volume and walks into the same wall. On a bare `--run` the
stop covers all three tracks. Work in flight always finishes.

Recovery has three cases:

- **`failed` is terminal.** A drain runs `queued` rows and nothing else, so the
  volume that stopped the drain is skipped by every later run until you re-add
  it. This is easy to miss: a drain that silently skips one volume of thirty
  looks exactly like a drain that had twenty-nine.

  ```sh
  uv run autogeoref queue --track <track> --add <volume>
  ```

  The console's Retry button does the same thing. The failed row stays on the
  board; the new row beside it is the live one. A re-add lands in a drain
  that's still running, since the loop re-reads the queue file every iteration.
  An empty `fetch` queue ends that lane for good; `place` and `serve` keep
  polling while their upstream lane is alive.

- **A `running` row with nobody behind it** (host slept, session closed)
  refuses a re-add. Don't wait for a drain to settle it, because a drain with
  nothing else queued settles and exits in under a second. Drop it:

  ```sh
  uv run autogeoref queue --remove <volume> --track <track>
  uv run autogeoref queue --track <track> --add <volume>
  ```

- **A serve leg that baked but didn't publish** leaves `publish-owed.json` in
  the work tree, and the next serve drain publishes from it in seconds.
  Re-queueing instead repeats the whole bake, because `warp`, `mask`, and
  `mosaic` declare no outputs so `dag.is_fresh` can never skip them. To finish
  it by hand:

  ```sh
  uv run autogeoref publish <volume> --work <work> --city <city-config>
  ```

  With no marker the bake itself didn't finish and the entry needs a re-add.
  Fetch and place legs have no marker, so they always land there.

After a model limit, check for `*.failed.json` retry markers before re-running.
A marked page reads as cached, so a plain retry fails instantly at zero spend
until they're cleared. The console offers that and names the re-read it costs.

`cache/loc/` holds every response the client fetched and a hit issues no
request, which makes re-running catalog work free. Image bodies are dropped
once the file is safely under `work/<vid>/jp2/`.

## Console

```sh
uv run autogeoref queue --serve --city <city-config>
```

A browser board: what can I run, what's running, what needs a human. It derives
its work list from `status` and the queue and computes no counts of its own,
and its buttons call the same functions you'd call from the CLI.

Binds loopback and checks the Host header. That is the whole security model.
Don't put it on a network.

## Review

Optional. Walks a volume's flagged pool, shows each sheet as a ghost over
modern centerlines and its committed neighbors, records verdicts. Also
localhost-only.

```sh
uv run autogeoref review --city <city-config> --work work --volume <volume>
uv run autogeoref review --city <city-config> --work work --apply
```

Edits land in sidecars at `work/<volume>/review/p<N>.json`. `--apply`
materializes them into `OK (reviewer-verified)` results, re-runs the cutline
dry-run for edited masks, and re-warps. Then run the `rerun_hint` it prints to
redo masks, mosaic, and tiles.

Reviewer-verified sheets are committed-grade: they vouch in corroboration and
join the back half. They're pinned out of the seam solve and excluded from
every auto-acceptance statistic. Applying a verdict against a committed sheet
records dissent and never auto-revokes. `docs/INTERNALS.md` has the frames and
the edit math.

To QA a trial arm, point `--work` at the arm and pass `--all`, since QA targets
are accepted there and the default pool is flagged-only. **Never `--apply`
against an arm.** Arm sidecars vanish with the arm, so owner QA that gates an
enablement also needs a durable record of its own, with page list, verdict,
reviewer, and date.

`--render <dir>` writes static ghost composites when no browser is available.

Two gotchas: kill a stray server with `pkill -f "[a]utogeoref review"`, and
`/api/apply` requires `Content-Type: application/json`, so a curl probe without
`-H` gets 415.

## Bake

Needs system GDAL. Read the volume report first.

```sh
uv run autogeoref run <volume> --city <city-config> --work work --warp-only
```

`--city` supplies the one volume fact the bake reads: `content_masks` and its
per-page `content_mask_exempt`.

Queued equivalent, which is what to use when anyone is watching the console
(the board only shows live progress for queue-driven runs, and the queue blocks
a second run on the same tree):

```sh
uv run autogeoref queue --track serve --add <volume>
uv run autogeoref queue --track serve --run --city <city-config>
```

Masks default to the padded box of each sheet's printed color, so seams fall on
the sheet grid. `docs/INTERNALS.md` has the chain and defines every
`masks-qa.json` flag. Flags are advisory and surface in the report and in
`status`; investigate flagged sheets in the review UI before publishing.

**A volume baked before 2026-07-26** has neither the pre-split box expansion
nor the `coverage_gaps` statistic. Its tiles can show inter-sheet gaps and its
`masks-qa.json` has no `coverage` entry, which `status` reports as not
measured. Never read that absence as clean.

## Publish

```sh
uv run autogeoref publish <volume> --city <city-config> --work work
```

Validates the archive, lands it atomically, rewrites `exports/<volume>/`, and
rebuilds the viewer manifest in one recoverable operation. Review `git status`
afterwards and commit the exports tree.

- **Re-bake before publishing if you re-placed sheets**, or you export
  placements newer than the served tiles. `status --stale` lists volumes
  needing a serve pass.
- Publishing needs the volume's `sheets/manifest.json` and committed
  `results/`, even with an explicit `--source` archive, because the export is
  staged from the work tree.
- `exports/` holds committed sheets only: `gcps/p<N>.json` (result records
  verbatim, full-resolution pixels, seam-adjusted in place) and `allmaps.json`,
  one IIIF Georeference AnnotationPage that viewer.allmaps.org renders from any
  public URL. Allmaps fetches imagery from LOC's IIIF services, so no imagery
  is hosted here.
- Serialization is deterministic, so republishing an unchanged volume is
  byte-identical and a diff under `exports/` only ever shows a real placement
  change. `tests/test_release_metadata.py` fails if the tracked tree and what
  publish writes disagree.

A volume declaring `overview_pages` bakes its district plates to a separate
`<volume>-overview.pmtiles`. **Nothing serves that companion.** Old ones left
in a served tree are inert but still fetchable, and tens of megabytes each:

```sh
rm deploy/tiles/autogeoref/*-overview.pmtiles
```

The bake keeps its copy under `work/<volume>/`, so deleting costs no re-warp.

### One page per city

A manifest describes one city and lives at
`viewer/<city-slug>/manifest.json`. Nothing else may share that path; a
site-wide file once let `publish --city B` retitle city A's page with no error
anywhere.

Archives separate the same way. `publish` lands them in `deploy/tiles/<the
city's first serving_dirs entry>`; later entries are partner archives the city
vouches for and never writes. **A city serving under its own name must declare
`serving_dirs`**, or its volumes land unlabeled on the reference city's page.
`status --city` reads the same key, so without it a city publishing under its
own name reads as never baked.

The page resolves its manifest from `viewer/cities.json`, rebuilt by every
publish and manifest build. `?city=<slug>` loads one; with exactly one city
published, that one loads; with more, the page offers them.

Paths inside a manifest are relative to the manifest. `[viewer.basemap]` is
not: it names files vendored beside the _page_. In a deploy bundle the two are
one directory.

### Rebuilding a manifest

Only for an initial deployment or external archives.

```sh
uv run autogeoref viewer-manifest --city <city-config> \
  --pmtiles deploy/tiles/autogeoref
```

- Refuses a build that finds no archive. Bake first.
- Refuses any directory not in the city's `serving_dirs`, since every layer
  would publish under one site-wide credit line.
- Takes no publication lock and applies no metadata fallback. Don't run it
  against a live serve drain, and check the rebuilt titles.
- Every entry's `bounds` and `areas` come from the archive header, so a volume
  with no archive isn't in the manifest at all.

**No credit line is derived from the layers.** `optional_credits` is a config
string and an era bucket's `credits` overrides it for that era. Changing the
serving set never updates the credit, so check it by hand.

### Volume labels

Each volume is named by the first of: a `[viewer.labels]` entry, the LOC
catalog subject, its top community areas. Declare one when the catalog recorded
no usable name, then publish or rebuild.

```toml
[viewer.labels]
sanborn01790_190 = "1933 Century of Progress World's Fair"
```

### Viewing locally

```sh
make viewer          # http://127.0.0.1:8123/viewer/  (PORT=9000 to move it)
```

The walkthrough is a second page at `…/viewer/walkthrough.html`. It needs no
published city and no archives, so it is the one surface that works on a cold
clone. `#step=4` opens one panel, `#step=4&state=second` one of its states.

View state rides in the URL fragment as `#key=value&key=value`. Add new state
here; don't invent a second scheme. An unrecognized key is carried through
untouched.

| Key              | Value                    | Effect                              |
| ---------------- | ------------------------ | ----------------------------------- |
| `panel`          | `closed` / `open`        | side panel collapsed or expanded    |
| `at`             | `lng,lat,zoom`           | camera both panes open at           |
| `eras`           | comma-joined chip labels | which eras are on                   |
| `swipe`          | `0`–`1`                  | divider, as a fraction of map width |
| `off`            | comma-joined volume ids  | districts switched off              |
| `story` / `stop` | ids from `site.stories`  | opens that story at that stop       |

`at`, `eras`, and `swipe` are rewritten as the visitor moves. `off` ids are
checked against the manifest on open, so a withdrawn district doesn't ride
every forwarded copy of a link. `panel` is a property of the link: a visitor
arriving without it keeps their own last choice.

One flag lives in the query string, because it says what the page may _offer_:
`?stories=1` shows the guided-story entry list, `?stories=0` suppresses it even
for a reader arriving on a `#story=<id>` permalink.

## Deploy

```sh
bash scripts/deploy_site.sh --city <city-config> --dry-run
bash scripts/deploy_site.sh --city <city-config>
```

Rebuilds the bundle, uploads archives, publishes the page, then proves a range
request off the deployed archives works. Needs `rclone`, `curl`, and `npx` on
PATH plus the settings below. Run the dry run first.

**A newly baked volume is invisible until the page is redeployed.** The volume
list lives in the manifest inside the bundle, not beside the archives, so
uploading alone appears to succeed and changes nothing a visitor sees. Publish
the volume first; the script warns about an archive the manifest doesn't name,
which is exactly a bake whose publish never happened.

`--skip-upload` redeploys the page alone. The final manifest check reports
rather than gates, since a preview deployment and a lagging production alias
both read like a mismatch and are both fine.

To upload archives alone while a bake queue is still landing volumes:

```sh
bash scripts/push_archives.sh --city <city-config> --dry-run
bash scripts/push_archives.sh --city <city-config>
```

Basemap first, since the page can't draw without it.

**Never overwrite a published archive in place.** An archive keeps its name
across a re-bake, so a plain copy replaces the published object and a cache
holding byte ranges of the old one serves them beside ranges of the new.
`pmtiles.js` compares the ETag and drops the layer; nothing but the visitor's
console reports it. A local archive that differs is refused by name. When the
difference is a re-bake you meant to publish:

```sh
bash scripts/push_archives.sh --city <city-config> --replace <volume>
```

That uploads the one archive and purges its URL from the edge cache. A reader
who already has it open still hits the ETag check until they reload.

`deploy-bundle` alone prepares files without uploading. One bundle is one city:
the manifest sits beside the page files in `deploy/<city-slug>/`, so the
deployed page needs no city in its URL.

### Settings

From the environment, or an untracked `.env` in the repo root. Copy
`deploy.env.example`. An exported value wins over the file;
`AUTOGEOREF_ENV_FILE` names a different one.

| Variable                                        | Example                               | Required             |
| ----------------------------------------------- | ------------------------------------- | -------------------- |
| `AUTOGEOREF_TILES_BASE`                         | `https://tiles.example.com/chicago`   | yes                  |
| `AUTOGEOREF_R2_BUCKET`                          | `example-bucket`                      | yes                  |
| `AUTOGEOREF_PAGES_PROJECT`                      | `example-project`                     | yes, for the page    |
| `AUTOGEOREF_MAPBOX_TOKEN`                       | `pk.…`                                | yes, for the page    |
| `AUTOGEOREF_SITE_URL`                           | `https://example.com`                 | no                   |
| `AUTOGEOREF_R2_REMOTE`                          | rclone remote name, default `r2`      | no                   |
| `AUTOGEOREF_PAGES_ORIGIN`                       | default `https://<project>.pages.dev` | no                   |
| `AUTOGEOREF_CF_ZONE_ID`, `CLOUDFLARE_API_TOKEN` |                                       | only for `--replace` |

Bucket credentials are not among them: rclone holds the R2 access key in its
own config and the scripts name only the remote.

`AUTOGEOREF_SITE_URL` is the URL the PAGE is served at — the custom domain, not
the `pages.dev` alias. It fills `og:url`, the canonical link and `sitemap.xml`.
Without it the bundle still ships a real title and a description, and the pages
declare the small share card; the tags needing an absolute URL are left out,
because a wrong `og:url` sends everyone who shares the page somewhere else.
That includes `og:image`, which must be absolute or readers drop it — so with
no site URL a staged card is neither named nor shipped. The bundle also carries a
`404.html`, and its presence is what stops Cloudflare Pages answering every
unmatched path with `index.html` under a 200 — which is why `/robots.txt` used
to read as HTML.

The path on `AUTOGEOREF_TILES_BASE` is a per-city prefix, and it is what lets
one bucket serve several cities. Uploads are flat, so without a prefix a
duplicate basename replaces the wrong layer.

### The Mapbox token

`deploy-bundle` rewrites `config.js` from `AUTOGEOREF_MAPBOX_TOKEN` over the
repository's empty placeholder. Prefer the env var over `--mapbox-token`, which
lands in shell history and the process list. A secret `sk.` token is refused,
since the bundle would publish it verbatim.

Without a token the bundle still builds and the page reports search
unavailable. It does not fall back to Nominatim, whose public instance forbids
deployment traffic; that fallback is gated to localhost.

A city with a vector basemap serves it from the same public tile location, and
the deployed viewer has no other source, which is why the upload carries it
first. The basemap is the one archive whose name carries a date, so a refreshed
one ships under a new filename rather than through `--replace`.

## Cold-clone verification

Answered by running the tracked `Dockerfile`, not by reading the tree.

**Tier 1, cold.** Install, lint, strict typing, fast suite, wheel contract,
CLI. Ends `COLD-START-OK`. Not offline: `uv sync` and the wheel smoke resolve
against PyPI. Run before anything release-affecting: a dependency or lockfile
change, an edit to `Makefile` / `pyproject.toml` / setup docs, a new
system-binary dependency. `.github/workflows/cold-clone.yml` runs exactly this.

```sh
docker build -t autogeoref-cold . && docker run --rm autogeoref-cold
```

**Tier 2, with fixtures.** Run whenever fixture-bound behavior moves: gates,
schemas, goldens. It is the only way to watch the skipped golden tests run
against a tree that arrived by clone. `:ro` enforces the read-only fixture rule
by kernel.

```sh
docker run --rm -v "$PWD/fixtures:/app/fixtures:ro" \
  autogeoref-cold bash -lc 'uv run --all-extras pytest -n 8 --dist loadfile'
```

**Tier 3, a stranger's whole path.** Network on, credentials in, no fixture
mount. Spends model budget, so it is owner-approved and manual. Price it by
enumeration first; an estimate that is wildly off is itself a finding.

```sh
CITY=configs/staunton/staunton.toml
VOLUME=sanborn02165_007
uv run python scripts/fetch_loc_volume.py $VOLUME
uv run autogeoref prep $VOLUME --work work
uv run autogeoref run $VOLUME --city $CITY --work work --dry-run
uv run autogeoref run $VOLUME --city $CITY --work work             # spends
uv run autogeoref report $VOLUME --work work
uv run autogeoref run $VOLUME --city $CITY --work work --warp-only # needs GDAL
uv run autogeoref publish $VOLUME --city $CITY --work work
make viewer
```

`.dockerignore` has a job: make the build context equal the tracked tree. Check it by enumerating files in the image and diffing against
`git ls-files` both ways. `tests/test_docker_context.py` holds the half a test
can reach without a daemon. A pattern there is anchored at the context root,
where the same `.gitignore` line matches at any depth, so re-check after any
change to the ignore rules.
